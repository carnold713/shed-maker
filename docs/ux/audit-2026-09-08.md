# UX audit — Barn Designer editor · 2026-09-08

**Author:** UI/UX Designer agent (`agents/ux.md`). **Scope:** editor shell, plan, 3D stage, inspector, home page, new-barn flow. **Changed:** nothing — this is a critique and a spec.

**Evidence.** Screenshots `test-results/editor.png`, `envelope.png`, `interior.png`, `exterior.png`, `renderer.png`, `renderer-exterior.png` (the `shot-layout-*.png` files named in the brief do not exist; these six are the current state — captured by `tests/e2e/*.spec.ts`, so each one is a real user path). Code: `components/{editor,plan,inspector,scene,menus}`, `lib/store/*`, `app/page.tsx`, `app/new/page.tsx`.

**Owner's complaint, verbatim:** "from a UX perspective it's really complicated, I don't really know what I'm clicking on half the time, and the screens are all really cluttered."

**Verdict.** M1–M3 shipped a lot of capability and the shell shows *all of it at once*: four ways to change the view, checks in three places, six always-open panels stacked in the dock, a two-row tool strip floating over the plan, a 160 px footer of numbers, and a project panel that is invisible below 1536 px. The default barn is an empty white box with no next action; the only "start here" copy is the fifth line of a panel. The step-flow plan is right in spirit. Below I tighten it (six steps, different order, no placeholder steps, one panel, one view control) and specify the conventions that make "what am I clicking" obvious.

## 1. Screen-by-screen problems

Severity: **blocker** = stops or misleads a first-time user · **major** = real confusion or lost time · **minor** = polish.

### 1.1 Shell — every screenshot

- **blocker · Four competing view controls.** Rail icons 3D / Plan / Split (`Rail.tsx:55-63`), a centre chip group Split / 3D / Plan (`Editor.tsx:88-95`, comment says "for tests"), the 3D preset chips Exterior / Framing / Dollhouse / Interior / Iso (`Viewer.tsx:114-124`), and a View ▸ submenu in every right-click menu (`buildMenu.ts:50-59`). A user cannot tell which one "the view" is. **Fix:** one segmented control in the stage's top bar — `Plan | Both | 3D` — plus one `View ▾` dropdown for the 3D look (§2.8). Delete the rail view buttons and the centre chips; keep the menu items (they are the fast path, not the UI).
- **blocker · Checks live in three places at once.** Footer "Checks" card (`BottomCards.tsx:52-84`), `CheckPanel` docked under the inspector (`Editor.tsx:98-102`, and the rail "Checks" button merely moves it above the inspector — `checksOpen`), and the status pill in the project panel (`ProjectPanel.tsx:74-77`). Same finding, three renderings, three truncations. **Fix:** one Check step (§2.6) + one chip in the status bar.
- **blocker · Dead and misleading primary buttons.** "Builder pack (coming in M4)" in the rail does nothing (`Rail.tsx:67-69`, `onPack` just closes checks). "Share" copies the current URL and toasts "share links with builder access arrive in M4" (`StageHeader.tsx:43-51`) — the link only works for the same login. "Download" saves a PNG of the 3D canvas through a `window.__barnScreenshot` hook with no hint of what is downloaded (`StageHeader.tsx:72`). "More" opens the viewport context menu at a fixed fallback position because `Action` drops the click event (`StageHeader.tsx:16-23, 73`). **Fix:** remove all four from the header; "Copy link", "Download picture (PNG)", "Save a version" move into the Blueprints step and the `⋯` overflow. Never ship a button whose label promises a later milestone.
- **blocker · The project panel is hidden on normal laptops.** `ProjectPanel` renders in flow only at `2xl` (≥1536 px, `Editor.tsx:61-68`); below that it is a drawer behind an unlabeled icon. Every screenshot (1280 / 1400 px) hides it, so the *only* way to rename the barn, write builder notes, or save a version is undiscoverable — the hero title `<h1>` is not editable (`StageHeader.tsx:56`). **Fix:** editable title in the top bar (click to rename), notes/versions in the Project step; delete the drawer.
- **major · Hero header eats the stage.** 2.2 rem title + subtitle + Undo/Redo chips (`StageHeader.tsx:54-69`), and the plan is pushed down by `pt-28` = 112 px (`Editor.tsx:75`) while the tool palette still floats over it. At 720 px tall the plan gets ~55 % of its column. **Fix:** 44 px top bar: title (1.1 rem, editable) · save dot · Undo/Redo · `Plan | Both | 3D` · `View ▾` · Fit · `⋯`. Subtitle facts move to the status bar.
- **major · Footer cards are a number wall.** Six stat tiles + a row of lumber-size chips + "estimates · full BOM in the Builder Pack (M4)" (`BottomCards.tsx:18-50`), always on, 160 px tall, and the three top findings truncate mid-sentence (`:77`). "3,609 bf", "17.5 yd³" are unexplained units. **Fix:** 28 px status bar (§2.9). The full materials list is a Blueprints panel.
- **major · Rail is a grab bag.** "MENU" label (`Rail.tsx:49`) means nothing; the help icon opens the SPEC on GitHub in a new tab (`Rail.tsx:71`) — a developer artifact in the product nav; two of six buttons are utilities that reorder panels. **Fix:** the rail *is* the step list (§2.1); Help becomes "Shortcuts & tips".
- **major · Dock toggle is a 7 px tab** with a `›` glyph at mid-height (`InspectorDock.tsx:9-17`). Nobody will find it, and nobody should need it once one panel is shown at a time. **Fix:** remove; the dock is always present and 21 rem.
- **major · Undo/Redo exist twice** in code — `StageHeader` chips and `Toolbar.tsx:48-53` (`Toolbar` is dead: not rendered anywhere, only its `ViewMode` type is imported — `Editor.tsx:11`). `Save version` is also duplicated (`Toolbar.tsx:70`, `ProjectPanel.tsx:110`) and uses `window.prompt`. **Fix:** delete `Toolbar.tsx`; one Undo/Redo in the top bar; version label as an inline field.
- **minor · Pluralization bugs** visible in every subtitle and panel title: "1 openings" (`StageHeader.tsx:37`), "1 warnings" (`CheckPanel.tsx:54`), "0 ZONES · 0 PENS". **Fix:** a `plural(n, "warning")` helper in `lib/units.ts`; use it everywhere a count is shown.
- **minor · Project panel "Design progress" chart is decorative noise** — 36 bars with heights from `(i*37)%45` (`ProjectPanel.tsx:90-94`), i.e. random. The step list under it is the useful part and maps 1:1 onto the proposed rail steps. **Fix:** delete the chart; the rail shows per-step status dots instead.

### 1.2 Plan (left column in `editor.png`, `interior.png`, `envelope.png`, `renderer*.png`)

- **blocker · The tool strip wraps to two rows and sits on the drawing.** At split width the palette (`ToolPalette.tsx:41-53`) wraps ("Lean-to | Erase" on row 2), covers the north handle, and the plan's north arrow (`PlanView.tsx:562`, at `size.w-28, 36`) renders *inside* the palette row — see the "▲ N" between "Window" and the strip edge in `editor.png`. The door picker (16 text chips, `ToolPalette.tsx:55-62`) and window picker (9) add a third floating row. **Fix:** tools leave the canvas and become labelled icon buttons with dropdown pickers in the step panel (§2.3, §2.5). The plan gets its full column (drop `pt-28`).
- **major · Tools are text-only chips with no icons, no hint until armed.** A first-time user reads "Pen · Aisle · Room · Door · Window · Lean-to · Erase" as nouns, not actions. "Pen" is also the word for a writing tool. **Fix:** icon + label + one-line hint (§4); "Stall" not "Pen" for horses (the species preset decides the word: stall for horse/pony/cattle, pen otherwise).
- **major · Erase is a second way to delete with a wrong cursor.** `cursor-not-allowed` (`PlanView.tsx:224`) is the "you can't do this" cursor; the tool *does* something destructive on click. Delete key, right-click → Delete, and the Delete button already exist. **Fix:** remove the Erase tool.
- **major · Clicking a wall selects "the building".** `PlanView.tsx:410-421` calls `select("footprint")`; the whole outline turns orange and the dock shows six panels titled Interior / Footprint / Frame / Roof / … — nothing says "Building selected" and the wall itself has no properties (SPEC §3.4 promises a wall panel). **Fix:** clicking a wall selects *that wall*: dock header "South wall · 38' · 2 doors, 1 window", with its openings listed and "Add door / Add window / Add lean-to" buttons. Building-level fields live in the Building step, not behind a wall click.
- **major · Posts are ~4 px squares** (`postHalf = 5.5/24*scale` ≈ 2 px at the screenshot scales, `PlanView.tsx:218, 443-469`) with no hit padding; a near miss selects the wall. Selecting a post opens a spec sheet — Nominal / Actual / Stock / Treatment / Rule id truncated without wrapping (`envelope.png`, `Inspector.tsx:409-440`). **Fix:** 12 px minimum hit area; the member sheet stays (SPEC §3.4 provenance) but gets a plain first line ("6×6 corner post, 14' long, pressure-treated") and the rule/citation under a "Why this size?" expander.
- **major · The size handles are unlabeled orange pills** on the east and north edges only (`PlanView.tsx:527-558`). Nothing says they drag, nor why the west/south edges cannot. **Fix:** on hover show a tooltip "Drag to change width" / "Drag to change length" and the live dimension; keep two handles (the building is anchored at its south-west corner — say so once in the Building panel hint).
- **major · Selection, hover and error are four near-identical oranges.** Selected `#b5532a`, hovered `#d98a5f`, error `#c0392b` (`ZoneLayer.tsx:72`, `PlanView.tsx:450, 607`), accent `#ee7d2b` (`globals.css:9`). The user cannot tell "selected" from "wrong". **Fix:** one accent for hover/selection (accent at 60 % / 100 %), red *only* for errors and only as a badge + dashed outline, never a fill. Hex values also violate the persona standard (tokens only).
- **minor · Status line says "0 zones"** (`PlanView.tsx:570`) and "hd" for head count (`ZoneLayer.tsx:58`). **Fix:** "stalls" / "rooms"; "4 horses".
- **minor · Three formats for the same size:** "12'×12'" (`ZoneLayer.tsx:58`), "12×12" (presets), "12' × 12'" (inspector). **Fix:** one `formatSize(w, d)` → `12' × 12'`; presets show `12 × 12`.
- **minor · Picking a species / room / door in the store also arms the tool** (`useViewStore.ts:125-128`), which is why `InteriorPanel` has to immediately set the tool back (`ZoneInspector.tsx:136`). **Fix:** picking a variant must not change the tool; the tool button arms it.

### 1.3 3D stage (`exterior.png`, `renderer*.png`, right column elsewhere)

- **blocker · Hover paints an entire roof plane solid orange** — the triangle in `editor.png` is the roof under the cursor left by `page.locator("body").click()`. It reads as an error or a selection, not a hover. Selection in 3D is also a solid fill (the orange stall floor in `interior.png`). **Fix (3D lane):** outline / edge glow for hover and selection (`OutlineNode` is already on the 3D roadmap in the shell handoff); never a fill.
- **major · Preset names are jargon and collide with the step names.** "Dollhouse", "Iso", and an "Interior" preset next to an "Interior" panel and a proposed "Interior" step (`Viewer.tsx:19-24, 121`). **Fix:** `View ▾` with Outside · Inside · Framing only · Cutaway; "No perspective" as a checkbox inside it.
- **major · The cutaway control is always on screen** with a disabled slider when unchecked (`Viewer.tsx:142-149`), and its hint line wraps *under* it at split width ("drag orbit · right-drag pan · right-click for menu · ridge 15' 10 1/2"", `Viewer.tsx:151-153`; overlapping in `editor.png`). **Fix:** slider appears only when the Cutaway view is chosen; the hint moves to the status bar and shortens.
- **major · Camera does not frame what you just added.** In `exterior.png` the user built a 10' enclosed lean-to on the west wall and the camera still looks from the south-east — the lean-to is invisible. Fit is only `F` or a menu item. **Fix:** a Fit button in the top bar; auto-fit after add lean-to / change size / apply layout (a `requestFit()` already exists).
- **major · Selecting something in a hidden layer gives no feedback.** In `envelope.png` a post is selected while the Exterior preset hides framing; nothing in 3D changes. **Fix:** when the selection's layer is hidden, ghost it through the skin (x-ray) or show "Hidden in this view — switch to Framing" in the status bar.
- **major · Layers is an eight-checkbox `<details>` on the stage** (`Viewer.tsx:127-139`). Advanced, rarely used. **Fix:** inside `View ▾`, under a divider.
- **minor · Default render is nearly invisible** — white walls, off-white roof, warm-white ground (`renderer-exterior.png`). A first-time user sees a faint box. **Fix (3D lane):** darker default roof (`roofColor` `#cfc8bd` → a mid grey) and a slightly cooler ground so the building separates; keep the studio look.

### 1.4 Right dock — building state (`editor.png`, `exterior.png`, `renderer*.png`)

- **blocker · Six stacked panels plus Check, always open, in an order that fights the workflow.** `BuildingInspector` renders Interior · Footprint · Frame · Roof · Concrete & lean-tos · Materials (`Inspector.tsx:74-243`) followed by `CheckPanel`. Interior comes first even for an empty shell; the Frame panel exposes eight builder controls (posts, foundation, girts, carrier, trusses, heel) at the same weight as width and length. **Fix:** one panel per step (§2); framing details behind "Advanced framing ▸".
- **major · The panel's instruction points at hidden UI.** "Draw pens, aisles and rooms on the plan with the tools at its top-left (P / A / R)" (`ZoneInspector.tsx:134`) is shown in 3D-only mode where there is no plan (`exterior.png`). **Fix:** tools live in the panel itself, so the instruction is the buttons.
- **major · Verbs without objects.** "Snap to 2'" (`Inspector.tsx:88`), "Fit building to interior", "Grow to fit" (`ZoneInspector.tsx:159-164`, both disabled with no reason when there are no stalls), "Clear", "Center aisle + tack". **Fix:** copy in §4; disabled buttons carry the reason in the tooltip and a muted line below ("Add a stall first").
- **major · Compass jargon on the two most-used fields.** "Width (E–W)" / "Depth (N–S)" (`Inspector.tsx:79-83`), "From west" / "From south" (`ZoneInspector.tsx:64-69`). Owners think in width across the roof and length along it. **Fix:** "Width (across the roof)" / "Length (along the ridge)", bound through `roof.ridgeAxis` so the labels stay true if the ridge is turned; compass letters as the hint.
- **major · "Footprint", "zones", "envelope", "bays", "girts", "carrier", "heel", "OC", "bf", "yd³"** appear in primary UI (`Inspector.tsx:77, 106, 147-167, 210-225`; `ZoneInspector.tsx:133`; `BottomCards.tsx:21-24`). **Fix:** §4 glossary; trade terms only inside Advanced groups and in the member sheet.
- **minor · "Materials" panel is three colour pickers** for siding/roof/trim (`Inspector.tsx:246-263`) — fine, but it belongs with doors and windows (Outside step), not under framing.
- **minor · The Interior panel title counts "0 ZONES · 0 PENS"** — jargon and a count of nothing.

## 2. Recommended information architecture

### 2.1 Steps (the left rail)

Six steps, icon + label, 76 px rail, in this order: **Project · Layout · Building · Outside · Check · Blueprints.** Changes from the brief and why:

- **Layout before Building.** With "grow the building" on (default), the interior drives the size (SPEC §18, ADR-0008). If Building comes first, the user sets 24×36, then picks a centre-aisle layout, and their size silently becomes 38×40 — the step they just finished got overwritten. Layout first tells the true story: *stalls first, the building fits them*; Building then shows the derived size and the user adjusts. An outside-in user simply clicks Building first — steps are a menu, not a wizard.
- **"Layout" not "Interior", "Outside" not "Exterior".** "Layout" says what you do there; "Interior/Exterior" collide with the 3D preset names. Keep "Interior"/"Exterior" if the presets are renamed first (§2.8) — but the verbs are better.
- **No "Electrical" step until MEP exists** (M7, agent pending). A rail entry for a missing feature is the "Builder pack (coming in M4)" mistake again. Reserve its slot after Outside; add it when `rules/mep` ships.
- **"Blueprints" stays** as the name — evocative and honest as long as the step *does something today* (materials list, plan picture, PNG, link, versions) and marks the PDF set as coming without a button for it.

Rail extras: home/logo at top; each step shows a status dot (empty · started · done, from the `designProgress` predicates); Check shows a red count (errors) or amber count (warnings) badge; "Help" at the bottom opens a shortcuts sheet. Keyboard: `Ctrl/Cmd+1…6` jumps to a step.

### 2.2 The stage

One stage, one top bar (44 px), one status bar (28 px). The stage mode is a segmented control `Plan | Both | 3D`; each step sets a *default* the user can override (their choice sticks per step). Divider between plan and 3D is draggable; per-step default ratios below. On viewports narrower than 1200 px, "Both" collapses to the step's primary view with a toggle.

### 2.3 Layout — stalls, aisle, rooms

- **Stage:** Both, plan-first (plan 60 % · 3D Inside cutaway 40 %). 3D auto-fits on layout apply.
- **Tools (icon buttons in the panel, one row):**
  - **Select** (arrow) — "Click to select · drag to move".
  - **Stall** (stall-front icon) + species dropdown — "Click inside the walls to add a 12' × 12' horse stall · drag to size it".
  - **Room ▾** (door-in-box icon) — dropdown: Tack room, Feed room, Hay & bedding, Wash bay, Equipment bay, Office, Utility, Kidding pen, Open area — "Click inside the walls to add a room".
  - **Aisle** (double-arrow icon) — "Click where the aisle should run · it spans the building".
  - **Layouts ▾** (grid icon) — Center aisle · Center aisle with tack & feed · Shed row · Remove all stalls & rooms — "Fill the barn with a proven pattern (you can edit everything after)".
- **Dock (nothing selected):** summary line "4 horse stalls · 14' aisle · 1 tack room"; the tool row; setting "Grow the building when a stall goes past a wall" (toggle, default on); buttons "Shrink building to fit the stalls" / "Grow building to fit the stalls" (disabled with reason "Add a stall first"); footer button **Next: Building →**.
- **Dock (stall selected):** header "← Layout · Horse 2"; fields per §4.2.
- **Empty state:** "No stalls yet. Pick a layout to fill the barn in one click, or choose Stall and click inside the walls."

### 2.4 Building — size, height, roof, frame, slab

- **Stage:** Both, 3D-first (3D Outside 60 % · plan 40 % with the two size handles). Fit after every size change.
- **Tools:** none on the canvas beyond the handles; everything is a field.
- **Dock:** Size (Width, Length, "1,520 sq ft", "Round to 2'"), Height (Wall height at the eave; ridge height read-out), Roof (Shape · Pitch · Ridge direction · Overhang), Frame (Pole barn / Stick-frame · Post spacing 8' / 10' / 12'), **Advanced framing ▸** collapsed with a one-line summary ("6×6 posts set in the ground · 2×6 girts · 2-ply 2×12 carrier · trusses every 4'"), Concrete (Slab on/off · thickness · aprons outside big doors). Footer **Next: Outside →**.
- **Empty state:** none needed; hint under Size: "Or drag the orange handles on the plan. The building grows from its south-west corner."

### 2.5 Outside — doors, windows, lean-tos, colours

- **Stage:** Both (plan for placing, 3D Outside for seeing; fit after add). 3D right-click on a wall keeps "Add door ▸ / Add window ▸".
- **Tools:**
  - **Door ▾** (door icon) — grouped dropdown: *Entry* (Entry door 3', Entry door 2'8", Entry door with window), *Double* (6', 8'), *Stall* (Dutch door 4'), *Sliding* (8×8, 10×10, 12×12, Sliding pair 16×12), *Overhead* (9×8, 10×10, 12×12, 16×12), *Roll-up* (10×10, 12×12) — "Pick a door, then click a wall to place it".
  - **Window ▾** (window icon) — Sliding 2×3 / 3×3 / 3×4, Single-hung 3×4, Fixed 4×4 / 4×6, Picture 6×4, Awning 3×2, Transom 6×2 — "Pick a window, then click a wall".
  - **Lean-to** (shed-roof icon) — "Click a wall to add a lean-to on that side".
  - **Colours** — three swatches (Siding · Roof · Trim) inline in the panel, not a tool.
- **Dock (nothing selected):** by wall — "South wall: Sliding door 10' × 10' · Window 3' × 4'" (each a link that selects); "Lean-tos: West, 10' enclosed"; Colours. Footer **Next: Check →**.
- **Dock (door selected):** header "← Outside · Sliding door · south wall"; fields per §4.4.
- **Empty state:** "No doors yet — every barn needs at least one. Choose Door, pick a size, then click a wall."

### 2.6 Check

- **Stage:** Both; hovering a finding highlights its item in plan and 3D; "Show me" selects it and fits the camera.
- **Dock:** three groups — Must fix (red) · Worth a look (amber) · Notes (blue). Each card: plain message · `[Fix: …]` primary button when a fix exists · "Why?" expander (rule title, source, rationale). Header line: "Red items must be fixed before the plans are ready. Yellow ones are worth a look." Footer **Next: Blueprints →**.
- **Empty state:** "All clear. Nothing to fix — your barn is ready for the plans."

### 2.7 Blueprints

- **Stage:** document view — the plan at print scale (the existing SVG with dimensions, no handles) and the 3D picture; later the sheet set.
- **Dock:** Materials (plain labels: "Posts 21 · Trusses 11 · Lumber 4,793 board feet · Roof steel 1,771 sq ft · Siding 1,830 sq ft · Concrete 23.6 cubic yards", then the lumber list), "Download picture (PNG)", "Download plan (PNG)", "Copy link" (with the honest hint "Anyone with your login. Builder links are coming."), "Save a version" (name field + list of versions), and a muted line "PDF plan set: next milestone" — text, not a button.
- **Empty state:** none (always has materials).

### 2.8 Project

- **Stage:** 3D Outside, fitted.
- **Dock:** Name · Notes for your builder · Animals & how many (the wizard answers; "Re-run layout" button re-applies the pattern) · Site: North direction (rotation control; the plan's N arrow follows) · Frost depth (inches) + "Verified with my building department" · Snow load (later). Footer **Next: Layout →**.
- **Empty state / hint:** "Nothing here is required, but a verified frost depth removes the warning on every plan."

### 2.9 Top bar, View menu, status bar

- **Top bar:** `[Barn name ✎]` · save dot (Saved / Saving… / Unsaved / Save failed) · Undo · Redo · `Plan | Both | 3D` · `View ▾` · Fit (⤢) · `⋯` (Download picture, Save a version, Keyboard shortcuts).
- **`View ▾`:** Outside · Inside · Framing only · Cutaway (shows the height slider only when chosen) · divider · Plain white / Colours · No perspective · Layers ▸.
- **Status bar:** left "38' × 40' · 1,520 sq ft · 5 stalls · 3 doors"; centre = the contextual line (§3.8); right "Materials ▸" (→ Blueprints) · "2 warnings" chip (→ Check; red when errors). Cost is **not** shown until a cost rule exists (SPEC §7.8 is P1) — a fake dollar figure is worse than none.

## 3. Interaction conventions (enforce everywhere)

1. **Selection.** Single left-click selects one thing; click empty space or press Esc to clear. Selected = 2 px accent outline + handles (8 on a stall, 2 on the building, a grab band on a door) in plan; the *same* outline in 3D (never a fill). The dock header names it with its icon: "Horse 2 · 12' × 12'". Selection survives view toggles and step changes; changing step keeps the selection only if that step owns it (a stall selected in Outside deselects).
2. **Hover.** Plan: accent outline at 60 % + the right cursor (pointer = selectable, move = draggable, resize arrows on handles). 3D: edge outline. The status bar's centre names the thing and its one-line hint ("South wall · 38' · right-click to add a door"). Tooltips with dimensions after 400 ms. Walls get a hover state (today they have none).
3. **Right-click.** Everything has a menu (keep `buildMenu.ts`). Rules: a header line naming the target; the most common verb first; "Properties" last; one level of submenu; trade options (girts, post size) at the bottom under a divider. Right-click also selects.
4. **Keyboard.** `Ctrl/Cmd+Z` undo · `Ctrl/Cmd+Shift+Z` / `Ctrl/Cmd+Y` redo · `Delete`/`Backspace` delete selection · arrows nudge (stalls 1', Shift 4'; doors 1", Shift 1') · `Ctrl/Cmd+D` duplicate (today plain `D` duplicates a stall *and* is the door hotkey — `Editor.tsx:147` beats `:168`; fix the collision) · tool letters `V` select, `S` stall, `R` room, `A` aisle, `D` door, `W` window, `L` lean-to · `F` fit · `X` cutaway · `Ctrl/Cmd+1…6` steps. Letters only when focus is on the stage (keep the `inField` guard, `Editor.tsx:121`). Every tooltip shows its key.
5. **Escape ladder**, one level per press: close menu/dropdown → cancel the drag in progress (restore the start state — not implemented today) → leave the tool (back to Select) → clear selection → nothing.
6. **Undo.** One step per gesture: a drag, a placement, a field commit, a layout apply (drags already coalesce — `PlanView.tsx:97-124`, keep). Undo never changes the step, the view, or the camera. Undo/Redo buttons show "Undo" / "Nothing to undo" tooltips.
7. **Entering and leaving a tool.** Enter: click the tool button (it shows pressed) or press its key; picking a variant in the dropdown also arms the tool. Armed: crosshair cursor, a snapped ghost follows the pointer with its dimensions, the status bar says exactly what a click does ("Click to place a 10' × 10' sliding door · Esc to cancel"). Invalid spot: ghost turns red with the reason ("Too close to the corner"). **Leave:** one placement returns to Select with the new item selected (Figma convention — the user placed it and is now editing it); Esc; clicking Select; changing step. Double-click a tool to pin it for repeated placing (pin badge; Esc unpins).
8. **"What am I clicking" is communicated three ways at once:** the cursor (semantics above; no `not-allowed` for a working tool), the ghost preview (placement) or outline (hover), and the status-bar centre line, which always reads *noun · fact · verb hint*. Hit areas are ≥ 12 px in plan (posts, door bands, handles).
9. **Colour discipline.** One accent for hover/selection. Red = error, amber = warning, blue = note, and they appear as badges and dashed outlines only. Token names from `globals.css`; no hex in components (persona standard).
10. **Feedback for hidden things.** If the selection is in a hidden 3D layer, x-ray it or say so in the status bar. If a button is disabled, the tooltip says why.
