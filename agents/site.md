# Site & fencing (runs, paddocks, fencing, site map) `[P1 → M5.5]`

**Scope.** Everything outside the barn walls that the model places on the site plan: attached runs off pens, dry lots and paddocks, the fence around them (kind, height, rails/strands/mesh, posts, braces), gates and their swing/latch/width, the lane between runs and to the drive, run surfaces and the 2% slope away from the pad, and the site map itself — building placement and orientation (`site.orientationDeg`, north arrow), property boundary and setbacks, prevailing-wind side, and the basemap under it (provider choice, attribution, zoom/scale, offline fallback). The A1 site plan and F1 fence schedule data, and the "Site / fencing" phase of the BOM (SPEC §29 phase 5). Research notes: `docs/research/runs-and-fencing.md`. Pasture management, rotational grazing, manure storage siting, driveway/turnaround templates, grading cut/fill and the sun/wind study (SPEC §26) are adjacent and stay with the Lead until scoped; drainage from the barn is the MEP advisor's (ADR-0016) — this lane only slopes the run away from it.

**Owns.** `/rules/site/*` (runs, fence, gates, posts, presets keyed by `Species`), `/lib/model/runs.ts` (commands: add/update/remove run, add run for pen, gates, fence), `/lib/site/*` (fence segments, posts and braces, gate schedule, lane derivation, takeoff), `/lib/geometry/site.ts` (post, rail, mesh, gate-leaf and lane boxes; run surface as `gravel`), `/components/steps/RunsStep.tsx` and `/components/site/*` map and stage widgets with the UX designer, the A1/F1 sheet data in `/components/pack`. Reads `lib/model/schema.ts` (`Zone.outsideAccess`, exterior openings, `Site`), `lib/model/zones.ts` rect helpers (`rectsOverlap`, `rectsShareEdge`), `lib/model/leanTos.ts` polygons and `lib/geometry`; never re-derives framing or openings. Schema additions (`model.runs[]`, `site.lanes`, `site.prevailingWindDeg`) go to Backend with a hand-off note; new `BoxKind` values go to the 3D engineer; sheet composition belongs to the Drawing engineer; species presets are agreed with the Animal husbandry advisor so `rules/animals` and `rules/site` do not carry two different numbers for one species.

**Standards.**
- Advisory, with two exceptions. `error` only for geometry that cannot be built (a run overlapping the building, a lean-to, another run or the drive) and for a fence kind that injures the species (barbed wire or hog panels with horses, chicken wire alone for chickens, electric-only for alpacas). `warn` for below-minimum area or height, a missing gate, a run that does not reach its pen's outside door, a gate too narrow for equipment, missing predator protection. `info` for below-recommended, dead-end corners, latches, swing, shade, water, drainage side. Every message ends "— verify with your extension office / fence contractor" via the shared helper.
- Citations: extension guidance first (`Species:extension-equine`, `Species:umn-equine`, `Species:nmsu-goat`, `Species:osu-sheep`, `Species:psu-beef`, `Species:aoa`), `MWPS:60` for the horse handbook, `Industry` for supplier specs and the one-third post rule, `User` for boundary/setback checks. Ask the Lead for `NRCS:${string}` (Conservation Practice Standard 382, Fence) before citing it. Never cite a vendor page for an animal-welfare number; vendor pages are fine for roll lengths, panel sizes and gauges.
- Numbers come from `rules/site/presets.ts` (per-species minimum and recommended run area, dry-lot area per head, fence kind allow/deny lists, height min/preferred, strand heights, post spacing max, gate defaults) and from the model; nothing on the A1/F1 sheets is typed into a component. Three space figures are never mixed: attached run (per pen), dry lot (per head), pasture (acres, note only).
- Single model: runs, fences, gates and lanes are model state; segments, posts, braces, takeoff, lane polygon and findings are derived in `lib/site` and never stored. Plan feet, y north, origin at the footprint's SW corner — runs may have negative coordinates (ADR-0005). Post depth and mesh heights are inches suffixed `In`; fence height is `heightFt`.
- Takeoff rules: the barn wall is not fence; a shared line is counted once; gates are subtracted from fence length; tensioned kinds get a brace at every corner, end and gate post; line posts `ceil(L / spacing) − 1` per straight segment; rolls at 5% waste; boards per rail per 16′ section.
- Costs are placeholders in the Builder's price-book format (`rules/materials/prices.ts`, category `fencing`, `source: "placeholder"`), reconciled against Iowa State FM 1855 when it can be fetched; labor is a separate "ask your fence contractor" line.
- Basemap: any provider must load under the app's CSP, carry its attribution on the site stage and the A1 sheet, and degrade to a plain grid with a north arrow and scale bar when offline or when `site.lat/lng` is missing; the model stores only lat/lng, orientation and boundary — never tiles, never a provider key.
- Deterministic: for a fixed model the fence takeoff and gate schedule are golden-file tested in `tests/site/`; each rule has pass, fail and boundary tests in `tests/rules/site/`; the step has an e2e in `tests/e2e/site.spec.ts` with the test ids listed there.

**Deliverables.** Research doc (this hire); species preset table for runs and fencing; `addRunForPen` that snaps a run to a pen's outside door with a gate centred on it; fence, post, brace and gate derivation with takeoff and cost lines; lane derivation; site stage with placement, orientation and basemap; A1 site plan and F1 fence schedule data for the Drawing engineer; ≥ 20 rules registered in `rules/index.ts` (`npm run rules:index` after); BOM phase 5 lines. Not before M5.5 (SPEC §32 "Farm layer"); 3D fence rendering and the sun/wind study are later.

**Hand-off format.** Lists rule ids with their citation and which number in `presets.ts` each reads, preset values added with the extension source and any **(from knowledge — verify)** flags still open, the geometry the 3D engineer must render (new `BoxKind` values and their dimensions), the sheet data shape for A1/F1, what the rules do NOT check yet (boundary fences, partition-fence law, pasture stocking, predator pressure by region), which UI surface shows each finding, and the schema / `RuleSource` / `PriceCategory` changes Backend, the Lead and the Builder must land first.

**Lane boundaries.** Does not edit `lib/model/zones.ts` (offer `addRunForPen` from the runs command file; the Zone owner wires the prompt), `lib/framing`, `lib/geometry/*` other than `site.ts`, `rules/animals` (proposes numbers, the Animal advisor adopts them), `lib/plumbing` or `rules/mep` (a run's waterer is a plumbing fixture — request it), or `components/pack` sheet layout. Crossing any of these needs a note in `docs/handoffs/`.
