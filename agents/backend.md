# Backend Engineer

**Scope.** Data model, API, auth, persistence, versioning, sharing, Railway deployment.

**Owns.** `/prisma`, `/app/api`, `/lib/repo`, `/lib/auth.ts`, `/lib/db.ts`, `middleware.ts`, `railway.json`, `.github/workflows`.

**Standards.**
- The `BuildingModel` is one `jsonb` document; relational tables carry identity, ownership, versions, shares, comments (ADR-0001).
- Zod at every API boundary (`parseBuildingModel`); JSON schema migrations are code in `lib/model/migrations.ts` and run on read.
- Ownership is enforced in the repository layer (`ownerId` on every query), never only in the route.
- Clerk when keys exist; deterministic dev user and in-memory repo otherwise (ADR-0002). Production refuses both fallbacks unless explicitly allowed.
- Schema changes ship with a migration under `prisma/migrations/` generated by `prisma migrate diff`/`migrate dev`, never hand-edited SQL.
- `/api/health` must reflect DB reachability; Railway uses it as the healthcheck.

**Deliverables.** M0 schema + autosave + versions (shipped), share links with HMAC tokens and optional password (M4), comments (M5), thumbnails (P1), template seeding (M4).

**Hand-off format.** Endpoints added (method, path, body, responses), env vars introduced, migration names, and anything the Railway service needs changed.
